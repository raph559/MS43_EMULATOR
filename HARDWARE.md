# MS43 hardware as the emulator models it

One entry per device: what it is, the evidence, and what is modelled or stubbed (design §5.3).

"UM" is the C167CR Derivatives User's Manual V3.1; "ISM" is the C166 Family Instruction Set
Manual V2.0 (local copies in `refs/`). Code addresses are CPU addresses (`SS:OOOO`) in the car
file; the CPU sees the program 8 segments above its file offset (0B:F99C is file 0x3F99C). Status
as of plan 3 (2026-10-20). "Stub" names the side of design §7's line: whether the stub sits between
the CPU and an output a check reads.

## On-chip

| Device | Evidence | Model |
|---|---|---|
| **CPU (C167CR)** | REPORT.md §1; ISM; UM ch. 4-5 | Full instruction set, flags per ISM ch. 5, traps (class A/B, TFR), interrupt arbitration, PEC (the request is acknowledged before the data moves). IDLE serves PEC requests without waking (UM §20.1). Timing: ISM Table 11 plus bus states. MUL/DIV complete in one step (not interruptible). Plan 3: the warm-idle spark angle, dead time, dwell and injection time agree with a hand calculation from the calibration at every call (MULU, DIVLU and saturation included) |
| **SFR / ESFR** | UM Table 22-4 (`src/Ms43Sim.Core/Bus/SfrTable.g.cs`) | Registers owned by a model go through it. Every other SFR is plain storage and each access goes into the inventory. On the car only F024h (XPERCON, absent on the C167CR) is left |
| **IRAM, XRAM** | UM §3; SYSCON.XPEN set by the boot | IRAM 00'F600-00'FDFF (register banks, system stack); XRAM 00'E000-00'E7FF while XPEN = 1 |
| **Watchdog** | UM ch. 13; WDTCON = 9201h at 00:2E64, EA01h at 0E:0140 | Full: fCPU/2 or /128, WDTREL, SRVWDT, DISWDT rules, reset with WDTR |
| **Ports P2-P8, P5** | UM ch. 7; P3.8 read as the EEPROM ready line at 0E:B2C2 | Latch, direction, open drain; a read gives the pin for an input and the latch for an output, so a read-modify-write copies input pins. P5 input-only; P5DIDIS and PICON stored. Pin changes drive captures, gates and the output capture. CAPCOM compare outputs change the latch. The PWM's P7 outputs are given as each pin's share of time high, not as edges; SSC, ASC0 and T3OUT/T6OUT do not drive pins. A CPU reset changes pins without PinChanged events |
| **SSC** | UM ch. 12; jobs 0-4 dispatched by XP0 (0E:B076), Reference facts of plan 2 | Master and slave, programming and operating views of SSCCON, continuous transfers, receive and transmit errors. A master character ends as one scheduled event that plays the clock edges to the selected slaves. Slave characters come from an external master (the monitoring module). A write in programming mode initialises the SSC and forgets an unread SSCRB (UM p. 12-4: it "will initialize the SSC"); plan 2's P0604 at every key-on was this. No start latency, no phase or baud-rate errors |
| **GPT1 (T2-T4), GPT2 (T5, T6, CAPREL)** | UM ch. 10; T4 is the 1 ms tick (`ADD T4,#0BB8h` at 0E:B590), T3/T5/T6 set up at key-on | Timer, gated and counter modes, up/down with TxEUD, over/underflow with TxOTL, T6 reload from CAPREL, T5 counting T6OTL, CAPIN capture with T5CLR. T3 gated by P3.6 measures the burn pulse. Reported: T3 incremental mode, T2/T4 reload, capture and concatenation, CT3, reserved modes |
| **CAPCOM (T0/T1, T7/T8, CC0-CC31)** | UM ch. 15; the crank on CC15 and T0IN/T7IN, the cams on CC13/CC14, injectors CC0-CC5 and coils CC6-CC11 | Timer and counter modes (T6 over/underflows, T0IN/T7IN edges), every capture and compare mode. A match is the timer stepping, reloading or being written by software to CCx (UM p. 15-15); a change of a channel's CCM field clears its once-per-period lock (the coil and knock channels depend on it). Reported: double-register compare mode |
| **ADC** | UM ch. 17; start-up scan at 0D:E272, the ADC handler at 0E:5744 | Fixed-channel single conversion with its conversion time from ADCTC/ADSTC; the channel is sampled when the conversion starts. Reported: auto-scan, continuous, wait-for-read and injection modes |
| **PWM** | UM ch. 16; set up at 0D:3BF8; PWM2 the throttle bridge, PWM0/PWM1 the VANOS solenoids | Mode 0 (edge aligned), shadow registers, PIRx and PWMIR. Each P7 pin's share of time high in the current period (the comparator XOR the latch while PENx = 1, the latch otherwise), and an event at every setting change; a PWx or PPx write takes effect at the next restart, which raises the event again. Reported: mode 1, burst, single shot |
| **ASC0** | UM ch. 11; DS2 (80F7h, S0BG 4Dh) and KWP (80D1h) set-ups | Asynchronous modes, frame lengths, parity generation, S0TBIR/S0TIR/S0RIR timing, overrun, loopback. Reported: synchronous mode. Received frames are clean |
| **CAN module (00'EF00-00'EFFF)** | UM ch. 18; set up at 0D:437C (CSR 0741h, BTR 3601h); the boot's message-RAM test at 00:2F12 | CSR, IR, BTR (with CCE), masks, the 2-bit MCR elements, transmission (lowest object first, 44 + 8·DLC + 3 bit times), reception into the matching object, the XP0 line. Not modelled: remote frames (reported), error counters, bus-off, the last-message mask. Every frame the ECU sends is acknowledged; the other nodes are the CAN partners (below) |

## The board

| Device | Evidence | Model |
|---|---|---|
| **Flash (AM29F400, CS0)** | REPORT.md §2; BUSCON0 = 45BFh at 00:2D5A | 512 KiB, mirrored every 512 KiB. Writes are recorded and ignored: no command state machine |
| **External RAM (CS2)** | ADDRSEL2 = 0401h at 00:2D4E; 8 KiB on the car (REPORT.md §9.5) | 8 KiB, mirrored in a larger window: the boot's 16 KiB test fails, as on the car |
| **Output latch (CS3, 0x080000)** | 47 word writes with `EXTP #020h` from FDCA, no reads; 0078h at 00:2DA0 and 0D:F52A | Write-only latch on D0-D7: bits 0-2 the multiplexer select, 3 chip B CS, 4 chip A CS, 5 main-relay hold, 6 monitoring-module CS, 7 EEPROM CS. Powers up as 78h. A read gives FFFFh and is reported |
| **Analog inputs and multiplexers** | AN0-AN15 as the start-up scan and the ADC handler read them; mux A on AN13, mux B on AN4 (latch bits 0-2) | Two input sets: key on with the engine stopped (plan 2: 12.6 V, 20 °C, pedal released) and warm idle (plan 3: coolant and oil 90 °C, intake air 33 °C, 101.3 kPa). An attached source overrides a channel: the throttle body drives AN11/AN12, the engine AN0 (MAF), AN14 (coil current) and AN15 (knock), and the battery follows the engine's phase on AN1/AN5 (÷ 5.2). VAREF 5.0 V, ideal converter |
| **Digital inputs** | P3.1/P3.5 brake switches; P8.6 the throttle shut-off feedback (CC22) | Listed inputs at their level (P3.1, P3.5, P8.6 low); every other input reads high (pull-ups). Inputs the board drives over time override the set: the crank on P2.15, P3.0 and P3.2, the cams on P2.14 and P2.13, the burn pulse on P3.6 |
| **M93C86 EEPROM (SSC job 4)** | Driver 0D:F616-F6D2, READ 0D:F63A; block loads under 0B:0418; after-run writes at 0D:82DE | x16 Microwire: READ, WRITE, ERASE, EWEN, EWDS, ERAL, WRAL; ready/busy on DO; write cycle 5 ms. Starts blank (owner) or from a 2,048-byte image. **Stub side:** not between the CPU and a checked output |
| **Output-driver chip A (SSC jobs 0-1)** | Job 0 at 0E:B116, result check FC1D = A6h | 16-bit shift register, SPI mode 1; "no fault" = the complement of its previous command; every command it latches is captured. **Stub:** always no fault; between the CPU and a checked output |
| **Output-driver chip B (SSC job 2)** | Job 2, result check FC22 = 96h (FD82.8); its four heater channels learn the lambda set-up (task 1Fh, 0A:3132) | 32-bit shift register answering the input set's status word once the monitoring module has sent its first ADh frame: FFFF FAFAh in both car input sets, the four lambda heaters open (unplugged), so the firmware concludes "no sensors" (80F7 = 1). **Stub:** a fixed status word; between the CPU and a checked output |
| **Monitoring module (SSC job 3)** | Task 24h (0E:09D2), frames and answer routines of plan 2's Reference facts | SPI master, 9-byte frames (12h, CFh, ADh), questions, toggle byte, error counter, ADC 6 mirror; expected answers from the firmware's own routines. A frame whose error counter is not zero asks the previous question again (0E:0C66-0E:0DD4): plan 2's open item 1, settled with no unexpected answer over 100 s. **Stub:** its shut-off path is not modelled, only reported; between the CPU and a checked output |
| **Throttle body** | E-gas start check 09:9A86 (E17A); FD0C.10; tracks AN12/AN11 | A velocity model on the H-bridge (P7.2's high share minus P6.5, while P6.7 enables), with a spring preload, Coulomb friction, a limp-home detent at 4.90° and stops at 0° and 88°; tracks V1 = 0.5078 + θ/20.914, V2 = 4.5117 − θ/20.914. The start check passes: the full adaptation from a blank EEPROM (2.0 s), the short check after a key-off. At warm idle the controller presses it onto its lower stop |
| **Knock chip, coil feedback** | AN14/AN15, P3.6 (T3IN) | 0 V and no burn pulse without an engine; with one, the engine's laws (below) |
| **K-line tester** | ASC0 DS2/KWP set-ups | **Stub:** none connected |
| **CS1 window (1 MiB at 0x100000)** | ADDRSEL1 = 1008h at 00:2D4A | No device. Reads FFFFh, accesses inventoried (none on the car) |
| **CS4 window, second CAN controller (00'EE00)** | ADDRSEL4 = 00E0h, BUSCON4 = 0648h; initialisation at 0E:1B6E is skipped on the car | Not modelled: it belongs to 16 KiB development units. XRAM and the on-chip CAN take priority; the rest of the window is inventoried |

## The engine and the car (plan 3)

Attached with `ms43sim run --engine warm-idle`; every law is an [assumption] whose constants come
from the research's verified ranges, and each run lists them.

| Model | Evidence | Model |
|---|---|---|
| **Engine shaft** | The 60−2 wheel read on CC15 (T0IN/T7IN), the gap check and sync (FD7A, E5AE), F900 at 0E:184E; cams on CC14/CC13 | Tooth N falls at 6N°, teeth 59/60 and 119/120 missing; the crank waveform on P2.15, P3.0 and P3.2; the intake cam high on [250.125° − a, 610.125° − a), the exhaust on [106.5° + r, 466.5° + r). One scheduler event per edge, the crank edges walked in order; an edge due on the cycle the speed or the cam offsets change fires first. Cylinder 1 fires at 690°, order 1-5-3-6-2-4 |
| **VANOS actuators** | Solenoids on P7.0 (PWM0) and P7.1 (PWM1); setpoints 8971/8ADF, adapted readings 8972/8AE0 | Each cam's offset follows its solenoid's drive (the share of time its pin is low, integrated exactly): x' = 400 °CRK/s × (drive − hold) above 500 rpm, −200 °CRK/s below; ranges 40.1 and 25.1 °CRK; hold duties 0.377 and 0.365 (the car's hold map at 90 °C and 14 V). The firmware's forced solenoid pulses every few seconds move the cam briefly |
| **Idle air and combustion** | Idle valve on P2.12 (CAPCOM), target 8878 = 900 rpm at 90 °C | Valve flow 50 kg/h × the share of time P2.12 is low, capped at 480 mg/stroke; a 50 ms manifold lag; running, the speed follows the airflow at 105 mg/stroke with a 0.3 s lag. Combustion: a spark (a falling coil pin) and an injector closing within 0.25 s. The starter turns 200 rpm for 1 s from 3.0 s; the battery reads 12.6, 10.5 and 14.0 V in the phases. No torque model, no throttle air |
| **Engine sensors** | MAF read every 1 ms through `id_maf_tab__v_maf` (0x70EC6); knock windows CC21/CC31; `igcfb` on T3 | MAF: the car's table frozen as the sensor's law; knock: (c(n) + 0.5) × 5 / 256 V from `ip_nl_sp__n` (0x77CBB), 0 V below 50 rpm; coil current 2.7 V while turning; P3.6 high for 1.2 ms after each spark, retriggered. **Stub:** non-checked side |
| **CAN partners** | Learning in the first 10 s (FD9C, FD20, FD22); timeouts P1612/P1613; 615h byte 3 the ambient temperature | ASC1 153h every 10 ms; the cluster's INSTR2 613h and INSTR3 615h every 200 ms, fixed healthy contents (100,000 km, fuel 40, +20 °C); from 100 ms after power-on, only while the key is on. Never 43Fh, 43Dh, 1F3h or 1F5h [owner: an ASC car]. **Stub:** fixed contents; not between the CPU and a checked output |
| **Fault-memory reader** | State records 91DAh + 12·p, list A 9974h, list B 9A16h, descriptors file 0x6D08E + 22·p; the after-run record EEPROM 0x56-0xD5 (CRC-16/ARC from 000Fh) | Decodes the 162 paths (XDF names, DS2 codes, P-codes, type, status, environment) and the EEPROM record, and explains the paths this car is expected to show, each only under the run's conditions and for its fault type: 80 `tout_asr_3` (DSC-only 1F3h, with the partners), 156 `tam_can` (until the first 615h, with the partners), 12 `t_es` (no engine-stop record, from a blank EEPROM). A layout without the 162 DS2 codes is not decoded |
| **Output capture** | — | Every edge of an output pin (with the crank angle in an engine run), each PWM setting as its P7 pin's high share, chip A's commands, the CS3 latch and the heater command FDD2 from the monitoring frames; per cylinder, injections and sparks beside the ECU's decisions (E46x, E47C, E4B8, FBAB). Written to `events.csv` |
